# Design

## Context

絵文字のリアクションは、利用者が `POST /s/[id]/react` へ送り、サーバーが入室の確認・絵文字の検証・連投の制限（`space:reactrate:` を `kv_incr` で数える）を通したものだけを、LiveKit のデータメッセージ（topic `nagi-space.reaction`）で入室者全員に配っている。利用者のトークンにはデータを送る権限が無い（`canPublishData: false`）ので、偽のリアクションや字幕は送れない。

- 字幕は space-agent が topic `nagi-space.caption` で配り、`Captions.svelte` が入室してからの分を200件まで持って表示する。
- 絵文字の流れる表示は `Reactions.svelte` が持ち、絵文字のシートもそこで開く。
- これまでサーバーが配る通知には「利用者が書いた文章を載せない」としてきた（Unicode 絵文字も1文字だけに絞っている）。コメントはこの方針を変え、利用者が書いた短い文章を配る初めての経路になる。

## Goals / Non-Goals

**Goals**

- コメントを、絵文字と同じ「サーバーが確かめてから配る」経路に載せ、利用者がデータを直接送れない作りを保つ。
- 字幕とコメントを1つの欄で時系列に並べる。

**Non-Goals**

- 返信・削除・編集・コメントだけの禁止。
- 文面の自動のフィルター（全肯定の場の文化と、ホストの退室処分・通報で扱う）。

## Decisions

### D1. コメントは専用の API とリアクションと同じ topic で配る

- `POST /s/[id]/comment`（本文 `{ text }`）を足す。入室の確認・botたんSpace の拒否・文面の検証・連投の制限を通ったものだけを、`nagi-space.reaction` で `{ type: 'comment', from, text }` として配る。
- topic を分けない理由：画面側は今もリアクションの topic を「サーバーからだけ受け付ける」と決めて受けている。同じ topic にすれば、受け付けの条件をそのまま使える。`type` で絵文字と分ける。
- 代わりの案：利用者にデータを送る権限を与える → 偽の送り主や連投の制限をすり抜けられるので採らない。

### D2. 文面の検証

- 前後の空白を取り、改行・タブ・制御文字（`\p{Cc}`）・書式文字（`\p{Cf}`、ゼロ幅文字や向きを変える文字）を空白1つに置き換えてから、連続する空白を1つにまとめる。
- 書記素（`Intl.Segmenter`）で数えて1〜30字だけを受け付ける。空白だけなら拒否する。
- 画面では Svelte の文字としての差し込みだけを使い、`{@html}` は使わない（COMM-03）。

### D3. 連投の制限は別の枠で数える

`space:commentrate:{spaceId}:{did}` を10秒の期限付きで数え、3件を超えたら 429 を返す。絵文字の枠（8件／10秒）とは別に数えるので、絵文字を送っていてもコメントは送れる。

### D4. 「字幕とコメント」の欄

- `Captions.svelte` が字幕に加えてコメントも受け、1つの配列に `{ kind: 'caption' | 'comment', … }` として届いた順に積む（合わせて200件まで）。
- コメントの行には送った人のアイコン（20px）と吹き出しの印を付け、背景を一段変える。読み上げ用に「コメント」の語を行の頭に入れる（見た目では隠す）。
- 自動で追うのは、欄が下端から 24px 以内にあるときだけ。読み返している間は位置を動かさない。
- ミュートの判定は流れる表示と同じ `mutedDids` を使う。
- リアクションの topic を受ける処理は1つにまとめ、`type` が `reaction` なら流れる絵文字、`comment` なら流れるコメントと欄の行を作る。

### D5. 流れる表示

コメントも絵文字の層（D5 of refine-space-ui）を流れる。見た目は、アイコン付きの吹き出し（最大幅 240px、16px の文字、`--overlay` の面と hairline の線）にする。同時に表示する数は絵文字と合わせて30件まで。視差効果を減らす設定ではその場に出して消す。

### D6. リアクションのシート

操作バーの「絵文字」を「リアクション」にし（読み上げの名前は「リアクション」）、シートの上にコメントの入力欄（`maxlength` に頼らず書記素で数え、残りの字数を表示する）と送信ボタン、下に今の絵文字の選択を置く。送信中はボタンにスピナーを出す（LOOK-08）。botたんSpace では入力欄を出さない。

### D7. ヘルプのモーダル

- ヘッダーの右に「?」のアイコンボタン（読み上げは「ヘルプ」）を置き、`<dialog>` 要素の `showModal()` で開く。外側の操作の無効化・Esc での閉じる・フォーカスの扱いをブラウザに任せられ、閉じたら開いたボタンへフォーカスを戻す。
- 中身は、聴く・話す・リアクション・botたん・字幕とコメント・通報・保存しないこと の7項目を、アイコン付きの短い見出しと1〜2文で並べる。文面は日英を `messages.ts` に置く。
- Space画面で開いても、Space の接続や入力中のコメントには触れない（モーダルはヘッダーの部品の中だけで状態を持つ）。

## Risks / Trade-offs

- [声とは別の文字の会話が育つ] → 30字と10秒3件の制限。字幕と同じ欄に並べ、声の会話の流れの中に置く。
- [不適切な文面] → 自動のフィルターは入れない。ホストの退室処分（PART-06）、通報（PART-07）、Nagi のミュート（PART-09）で扱う。通報には文面が自動で入らないので、必要なら通報者が理由欄に書く。
- [コメントが多いと字幕が欄から押し出される] → 200件まで残し、読み返し中は位置を動かさない。
- [見えない文字で表示を崩す・なりすます] → D2 で制御文字と書式文字を取り除く。送り主の名前とアイコンはサーバーがプロフィールから付けるので、文面で名乗っても送り主は変わらない。

## Migration Plan

データの移行は無い。古い画面（デプロイ前に開いたままのタブ）は `type: 'comment'` を知らないので無視するだけで、壊れない。
