# Proposal

## Why

Nagi周辺には映像・音声の配信サービス（Bluecast、StreamPlace）はあるが、複数人がその場で声を交わす音声チャットが無い。Nagi Spaceは、Nagiの利用者が集まって話し、聴き、絵文字で反応できる場所を作る。会話に全肯定botたんを呼べるようにし、Nagiの「言葉を受け止める」体験を声でも提供する。

## What Changes

本リポジトリにNagi Spaceを新規に作る。既存の振る舞いの変更や削除は無い。

- **Nagiユーザー限定の利用**：AT Protocol OAuthでログインした、Nagiに登録済みの利用者だけが、Spaceの作成・入室・発話をできる。
- **Spaceの作成と種別**：「パブリックSpace」と「botたんSpace（ホストとbotたんだけの完全非公開）」を作れる。パブリックSpaceは開催中の一覧に出て、Nagiユーザーなら誰でも入室できる。
- **入室と参加の区別**：入室（聴くだけ）と参加（スピーカーとして話す）を分ける。聴衆は発話をリクエストし、ホストが承認するとスピーカーになる。
- **絵文字リアクション**：入室者は、Nagiの絵文字パレットと同じUnicode絵文字とカスタム絵文字をSpaceへ送れる。聴くだけ・絵文字を送るだけの参加もできる。
- **botたんの参加・除外**：ホストはいつでもbotたんを招待・除外できる。botたんはbot-tan-convoによって、話者ごとの名前付き発話を受け取って会話する。参加中は3Dモデル（VRM）を表示して動かす。convoの空きが無ければ「botたんは今いっぱい」と表示し、招待できない（待ち行列は作らない）。
- **自動文字起こし**：botたんの有無にかかわらず、全スピーカーの発話を音声認識で常に字幕にする。混雑時はbotたんの会話を優先し、botたんがいないSpaceの字幕を遅らせるか一時停止する。
- **保存しない**：録音も文字起こしも保存しない。Spaceが終わると破棄する。botたんの記憶にも残さない（BOT-07）。
- **Nagiへのシェア**：パブリックSpaceの開始時に、ホストのPDSへSpaceのリンクカード付き投稿を作るか選べる（本文は編集できる）。
- **モデレーション**：ホストはスピーカーをミュートし、発話権を取り消し、入室者を退室させて同じSpaceへの再入室を禁止できる。参加者は誰でも運営へ通報できる。
- **常に誰でも入れる場にする**：パブリックSpaceは必ず一覧に出し、Nagiユーザーなら誰でも入室できる状態を保つ。招待制・入室のロックなど、特定の人だけに閉じた会話にする機能と、利用者どうしの個別メッセージ（DMなど）は作らない（下記「法規との関係」）。
- **上限**：スピーカーはホストを含めて13人、入室者は100人、開催は4時間まで（いずれも設定値）。
- **見た目**：Nagiのデフォルトテーマに合わせ、ライト・ダーク（端末設定に追従を含む）を切り替えられる。faviconとOGPはNagiブランドに似せた独自のものにする。

## Capabilities

### New Capabilities

- `space-access`：Nagiユーザー限定のログイン、セッション、Nagi登録状態の確認。
- `space-lifecycle`：Spaceの作成・種別・開始・終了、開催中の一覧、開始時のNagiへのシェア。
- `space-participation`：入室・退室、ロール（ホスト・スピーカー・聴衆）、発話リクエストと承認、人間どうしの1対1の制限、ホストのモデレーション、通報。
- `space-reactions`：絵文字リアクションの送信と表示。
- `space-transcription`：全スピーカーの発話を音声認識で字幕にすることと、混雑時の優先度、保存しないこと。
- `bot-tan-presence`：botたんの招待・除外、convoのセッション容量、複数話者との会話、3Dモデルの表示。
- `space-appearance`：テーマ（ライト・ダーク）、favicon、OGP、レイアウト。

### Modified Capabilities

なし（本リポジトリに既存の仕様は無い）。

## 法規との関係（電気通信事業法）

総務省「電気通信事業参入マニュアル［追補版］」（令和5年1月30日改定）の事例を読むと、登録・届出の要否は人数ではなく、**誰でも入れる「場」か、特定の利用者だけに閉じた会話か**で分かれている。

- 「オープン・チャット」（不特定多数がリアルタイムで会話できる「場」）は、リアルタイムの電子掲示板とみなされ、他人の通信を媒介しないので登録・届出は不要（第三号事業）。
- 「クローズド・チャット／オンライン会議」（特定の利用者の間だけに閉じた会話）は、他人の通信の媒介に当たり、届出が必要。
- 「場」であっても、その一部に利用者間のメッセージを媒介する機能があれば届出が必要。
- 事業者と利用者の間の通信は媒介に当たらない（botたんSpace）。

Nagi Spaceは届出を出さない前提とし、パブリックSpaceをオープン・チャットと同じ性質に保つ（PART-05・PART-10）。オープン・チャットの事例は「文字ベースの会話」と書かれているが、事例の分かれ目は「誰でも入れる場か、特定の利用者に閉じた会話か」であり、文字か音声かではない。音声のパブリックSpaceも一覧に出てNagiユーザーなら誰でも入れるため、オープン・チャットと同じ扱いと整理した。利用者の規模も小さい見込みのため、総合通信局への事前相談はしない（2026-11-27 利用者と決定）。これは法的な判断ではなく、マニュアルの事例からの整理である。

次のどれかに当たる機能を加えるときは、届出の要否を考え直す（必要なら総合通信局へ相談する）。

- 招待制・入室のロック・一覧に出さないパブリックSpaceなど、特定の人だけに閉じた会話にする機能（PART-05）
- 利用者どうしの個別メッセージ（DMなど）や、Space内で特定の相手にだけ届く機能（PART-10）
- 利用料の徴収や広告など、Nagi Spaceとして収益を得ること

- 出典：https://www.soumu.go.jp/main_content/000477428.pdf （p.3–4 用語、p.27–28 事例）

## 非対象

- 録音・アーカイブ・あとからの再生、文字起こしの保存
- 映像の配信・画面共有
- 共同ホスト
- Nagi画面内への「開催中のSpace」表示（nagi_client・AppViewの改修を伴うため、別のchangeで扱う）
- LiveKitのセルフホスト運用（公開前に再検討する。仕様はどちらでも動く形にする）

## Impact

- **本リポジトリ**：新規のSvelteKitアプリ（Web）、Space管理API、botたん中継プロセス（Tailscale側で動くPython）、字幕用の音声認識ワーカー。
- **外部サービス**：LiveKit Cloud（開発時は無料枠：参加者の接続時間 月5,000分、同時接続100。超えると新しい接続ができない）。
- **bot-tan-convo（外部リポジトリ）**：話者IDと名前の付いた発話の入力、複数話者に向けた返事、Space用プロファイル、外部からの文字起こし要求の受け付けに改修が必要。
- **Nagi AppView（外部リポジトリ）**：Nagi登録状態・利用者のミュート一覧の取得、通報の受け付け、カスタム絵文字の検索を本アプリから呼べる契約が必要。既存APIで足りるかは確認タスクで調べる。
- **nagi_client（外部リポジトリ）**：姉妹アプリSSOの許可originにNagi Spaceを加える必要がある可能性がある。
- **個人情報**：音声と字幕は中継・処理するが保存しない。本アプリが保存するのはSpaceの開催情報（ホスト・タイトル・開始終了時刻・退室禁止の対象）だけ。届出不要の場合でも、通信の秘密の保護と検閲の禁止は適用される。
