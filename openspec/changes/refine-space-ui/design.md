# Design

## Context

画面は Svelte 5 と Tailwind v4 で書かれ、色は `src/routes/layout.css` に Nagi のデフォルトテーマ（bot-mint）の値で定義済み（LOOK-01）。共通の部品は `.btn` / `.btn-primary` / `.card` の3つのクラスだけで、Space画面（`src/routes/s/[id]/+page.svelte`）は上から順に段落を積んだだけの構成になっている。

- botたんの3Dモデル（`src/lib/space/BotAvatar.svelte`）は `max-w-xs`（320px）の正方形の枠。描画の解像度は端末の倍率の2倍までに抑えてある。
- 絵文字（`src/lib/space/Reactions.svelte`）は画面の右下に小さな吹き出しで縦に積まれる。
- 参加者の一覧は名前とロールの文字だけ。参加者のアイコンの URL は LiveKit の参加者情報に入っていない。トークンの `name` には Nagi のプロフィールの表示名を入れている。
- 応答を待つ操作は、一部（botたんの招待など）がボタンを `disabled` にするだけで、待っていることは表示しない。
- Nagi 本体（`../nagi_client`）は、`Button`（primary / secondary / ghost / danger、sm / md / lg）、`Spinner`、ログアウト時の紹介（`GuestHero`）とランディング（`landing/`）を持つ。カードに影を付けず、線と面の色の差で区切る作り。

## Goals / Non-Goals

**Goals**

- 画面の部品（ボタン・スピナー・カード・アイコン・見出し）を Nagi 本体と同じ考え方の少数の部品にまとめ、全画面で使い回す。
- Space画面を「見出し → botたん → スピーカー → 字幕 → 聴衆 → 操作バー」の構成に作り直す（LOOK-07）。
- 既存の E2E テストが頼る `data-testid` と操作の名前（ボタンの文言）は、変える理由が無い限り保つ。

**Non-Goals**

- Nagi 本体の部品をパッケージとして共有すること（リポジトリが別で、Svelte の版も違う。考え方と寸法を写す）。
- 画面の状態管理（`room.svelte.ts`）やサーバーの API の作り直し。

## Decisions

### D1. 部品は Nagi 本体の API に合わせて本リポジトリに作る

`src/lib/ui/` に `Button.svelte`（variant：primary / secondary / ghost / danger、size：sm / md / lg、`href` でリンク、`pending` でスピナー）、`Spinner.svelte`、`Avatar.svelte`（アイコン、無ければ頭文字）を置く。Nagi 本体と同じ名前・同じ使い分けにしておくと、どちらかを直したときにもう一方へ写しやすい。

- 代わりの案：Tailwind のクラスをその場で並べ続ける → 画面ごとに見た目がずれる今の状態が続くので採らない。
- 色・角丸・余白は `layout.css` のトークン（Nagi の `tokens.css` と同じ値）だけを使う。生の色は `layout.css` 以外に書かない。

### D2. 応答を待つ操作は `pending` を1か所で持つ（LOOK-08）

- `fetch` で送る操作（発話のリクエスト・承認、botたんの招待、絵文字、通報、シェアの再試行、終了）は、呼び出し側が `pending` を立てて `Button` に渡す。スピナーの間は `aria-busy="true"` と `disabled` にし、ボタンの幅は元の文言の幅のまま、文言の上にスピナーを重ねる。
- フォームで送る操作（ログイン、Spaceの開始、ログアウト）は SvelteKit の `enhance` で送信中の状態を取り、画面が切り替わるまでスピナーを出す。JavaScript が無い場合も今までどおり送れる。
- マイクの切り替えと入室は LiveKit の処理を待つので、`room.svelte.ts` の操作が返すまでを `pending` とする。
- 失敗したら `pending` を戻し、近くに `role="alert"` で理由を出す（今の失敗表示の場所を使う）。

### D3. Space画面は1段の中央寄せと、下に固定した操作バー（LOOK-05・LOOK-07）

- 中身は幅640pxまでの1段。スマートフォンでは左右16pxの余白。
- 操作バーは画面の下に固定し（`position: fixed`、iPhone の下の余白 `safe-area-inset-bottom` を足す）、本文の下にバーの高さぶんの余白を取る。並びは「マイク（話せる人だけ）・絵文字・発話のリクエスト（聴衆だけ）・その他（通報など）・退室／終了」。
- 絵文字の選択は、操作バーの上に開く下からのシート（幅640pxまで）にする。
- ホスト向けの操作（発話のリクエストの承認、botたんの招待・除外、モデレーション）は、操作バーではなく本文の該当する参加者の近くに置く（承認はリクエストした人の行、モデレーションは参加者の行のメニュー）。

### D4. botたんは画面の幅いっぱいの枠で上半身を写す（BOT-05）

- 枠は縦横比 4:5、幅は中央の段いっぱい（最大640px）、高さは画面の高さの55%までに抑える。カメラは上半身（胸から上）を写す位置に寄せる。
- 大きくなるぶん描画の負荷が上がるので、解像度の上限は今の「端末の倍率の2倍まで」に加えて、描画の大きさが 1280×1600 を超えないようにする。タブが見えていないときは描画を止める。
- WebGL が使えないときのアイコンも同じ枠に大きく出す。

### D5. 絵文字はbotたんとスピーカーの段の上を流れる層に出す（REACT-01）

- 見出しの下から操作バーの上までを覆う、操作を受け付けない層（`pointer-events: none`）を置き、届いた絵文字をその中で下から上へ約3秒かけて流す。横の位置は届くたびにばらつかせる。
- 絵文字は48px（カスタム絵文字も同じ高さ）、左下に送った人のアイコン（20px）を重ねる。
- 同時に表示するのは30個まで。超えたら古いものから消す（大量に届いたときの描画の負荷を抑える）。
- `prefers-reduced-motion: reduce` のときは流さず、その場で表示して消す。
- アニメーションは CSS の `transform` と `opacity` だけで行い、配置の再計算を起こさない。

### D6. 参加者のアイコンは LiveKit の参加者情報に入れる（LOOK-07）

- 入室のトークンを発行するとき、参加者情報（metadata）に Nagi のプロフィールのアイコンの URL を足す（`{ role, avatar }`）。値はログイン時に AppView から取っているプロフィール（`locals.profile`）を使い、新しく問い合わせない。
- アイコンの URL は Nagi・Bluesky で公開されている情報で、LiveKit の room が終われば消える。本アプリには保存しない（LIFE-07 は変わらない）。
- ロールを変えるとき（`UpdateParticipant`）は metadata を上書きするので、アイコンの URL を消さないように、ロールだけでなくアイコンも含めて書き直す。
- botたんは本リポジトリの `static/bot-tan-icon.png` を使う。

### D7. ランディングはトップの未ログインの分岐に置く（LAND-01・LAND-02）

- `src/routes/+page.svelte` の未ログインの分岐を `src/lib/landing/Landing.svelte` に置き換える。サーバー側は今の `+page.server.ts` のまま（未ログインなら一覧を読まない）。
- 構成：見出し（キャッチコピーと短い説明）→ 主な操作「Nagiのアカウントではじめる」→ 特徴3つ（声で集まる／聴くだけ・絵文字だけでも／botたんを呼べる）→ 安心できる点（Nagiの利用者だけ・録音や文字起こしを残さない）→ 2つ目の導線とNagiへのリンク。
- Nagi 本体のランディングと同じく、言葉を並べるより「場の様子」を1つ見せる：見出しの横（スマートフォンでは下）に、Space画面の見本（botたん・アイコンの並び・流れる絵文字）を静的に描いた絵を置く。実際の Space の情報は使わない（LAND-01）。
- 文面は日英を `messages.ts` に置く。案は実装時に示して確定する（proposal の未決事項1）。

### D8. 仕上げは unslop スキルの順で行う

部品と構成を置き換えたあと、unslop スキルの手順（方向性 → 余白 → 色 → アイコン → 文言 → 文字 → 配置 → 細部 → 見た目 → 動き）で全画面を見直す。方向性は「Nagi の姉妹アプリ」で固定し、Nagi 本体の作り（影を付けない、線と面で区切る、角丸は 4 / 8 / 14px と丸）から外れる装飾（グラデーション、光る効果、絵文字の見出し、大文字の字間を空けたラベル）は入れない。

### D9. 確認の方法

- E2E：LAND-01・LAND-02（未ログイン・ログイン中・英語）、LOOK-08（サーバーの応答を遅らせてスピナーと二重送信の防止、失敗からの再試行）、LOOK-07（アイコンと頭文字、話している表示）、REACT-01（視差効果を減らす設定）、LOOK-05・BOT-05（幅360pxで横スクロールが出ない、操作バーが見えている）を足す。
- 見た目：ui-check スキルで、トップ（未ログイン・ログイン中）・ログイン・Spaceの開始・Space画面（botたんあり・なし）・終了画面を、幅360pxと1280px、ライトとダークで撮って確かめる。

## Risks / Trade-offs

- [3Dモデルが大きくなり、古いスマートフォンで描画が重くなる] → D4 の描画の大きさの上限と、見えていないときの停止。重い場合はフレームレートを30に落とす。
- [固定の操作バーが字幕や一覧の最後を隠す] → 本文の下にバーの高さぶんの余白を取り、幅360pxの E2E で最後の要素が見えることを確かめる。
- [絵文字が大量に届いて描画が重くなる・画面がうるさくなる] → 同時30個までに制限する。送信側には既存の連続送信の制限がある（REACT-03）。
- [文言やボタンの構成を変えて既存の E2E が壊れる] → `data-testid` を保ち、文言で探しているテストは同じ変更の中で直す。
- [metadata の上書きでアイコンが消える] → D6 のとおりロールの変更でもアイコンを書き直し、承認後もアイコンが出ることを E2E で確かめる。

## Migration Plan

画面だけの変更で、データの移行は無い。参加者情報の形（metadata に `avatar` を足す）は、古い形（`role` だけ）を受け取っても頭文字で表示できるように読むので、デプロイの途中で古いトークンの参加者がいても壊れない。問題があれば前のデプロイに戻す。

## Open Questions

- 絵文字の大きさ・流れる時間・同時の数の細かい値は、実際に見て調整する（D5 の値は初期値）。
- LP の見出しの絵に Nagi 本体の botたんの画像を流用するか（proposal の未決事項2）。流用しない場合は、本リポジトリの botたんのアイコンで同じ構成にする。
