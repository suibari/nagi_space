# space-comments Specification

## Purpose
Space の入室者が、声を出さずに短いテキストで反応できるようにする。コメントは入室者全員に同じように届き、画面を流れて消えるとともに、字幕と同じ欄に時系列で並ぶ。保存はしない。

機能一覧：

| 要件ID | 機能 |
|---|---|
| COMM-01 | コメントを送る |
| COMM-02 | コメントの表示（流れる表示と「字幕とコメント」の欄） |
| COMM-03 | 連投と内容の制限 |
| COMM-04 | コメントを残さない |
| COMM-05 | botたんはコメントを読まない |

主な利用の流れ：操作バーの「リアクション」を開く → 入力欄に30字までのコメントを書いて送る → 入室者全員の画面にコメントが流れ、「字幕とコメント」の欄に送った人のアイコン付きで並ぶ。

## Requirements

### Requirement: COMM-01 コメントを送る

パブリックSpaceに入室している人は、ロールにかかわらず30字（書記素で数える）までのテキストのコメントを送れなければならない（MUST）。コメントは入室者全員に届け、特定の相手にだけ送る方法を提供してはならない（MUST。PART-10）。入室していない人と、退室させられた人のコメントは受け付けない（MUST）。botたんSpaceではコメントの操作を出さず、サーバーも受け付けない。送信はマイクの許可を必要としない。

#### Scenario: 聴衆がコメントを送る

- **WHEN** 聴衆が「わかる」と書いて送る
- **THEN** 入室者全員の画面に、そのコメントが送った人の表示名とアイコンとともに表示される

#### Scenario: 30字を超える

- **WHEN** 参加者が31字以上のコメントを送ろうとする
- **THEN** 送信の操作は使えず、30字までであることが表示される。サーバーに直接送っても受け付けない

#### Scenario: 入室していない人が送る

- **WHEN** Space に入室していないログイン済みの利用者が、コメントの API を直接呼ぶ
- **THEN** サーバーは拒否し、誰にも届かない

#### Scenario: botたんSpace

- **WHEN** ホストが botたんSpace のリアクションのシートを開く
- **THEN** コメントの入力欄は表示されない

### Requirement: COMM-02 コメントの表示

届いたコメントは、絵文字と同じくSpace画面の上を流れる形で表示して数秒で消し、あわせて「字幕とコメント」の欄に字幕と届いた順に並べなければならない（MUST）。欄のコメントは、送った人のアイコンと吹き出しの印を付け、字幕と見分けられるようにし、読み上げでも「コメント」と伝える（MUST）。欄には入室してからのコメントと字幕だけを、合わせて直近200件まで残す。利用者が欄の下端にいるときだけ新しい行に自動で移り、読み返している間は位置を動かさない。送った人をNagiでミュートしている入室者の画面には、流れる表示にも欄にも出さない（MUST。PART-09）。字幕の一時停止（TRANS-03）の間もコメントは表示する。

#### Scenario: コメントが届く

- **WHEN** 入室中にほかの参加者からコメントが届く
- **THEN** コメントが画面を流れて消え、「字幕とコメント」の欄の最後に送った人のアイコン付きで加わる

#### Scenario: 欄を読み返している

- **WHEN** 利用者が欄を上にスクロールして前の字幕を読んでいる間に、新しいコメントが届く
- **THEN** 欄の表示位置は動かず、下端に戻ると新しい行が見える

#### Scenario: ミュートしている人のコメント

- **WHEN** 自分がNagiでミュートしている人がコメントを送る
- **THEN** 自分の画面には流れる表示にも欄にも出ず、ほかの入室者の画面には出る

#### Scenario: 字幕が一時停止している

- **WHEN** 混雑で字幕が一時停止している間にコメントが届く
- **THEN** コメントは流れる表示と欄に出る

### Requirement: COMM-03 連投と内容の制限

1人が短時間に大量のコメントを送れないよう、サーバー側で送信の回数を制限しなければならない（MUST）。制限は1人あたり10秒に3件とし、絵文字の制限（REACT-03）とは別に数える。制限を超えたコメントは他の参加者に表示せず、送った人には少し待つよう表示する。空白だけのコメントは受け付けない。改行と制御文字は取り除くか拒否し、コメントは常に文字として表示して、HTMLやリンクとして解釈してはならない（MUST）。

#### Scenario: 連投する

- **WHEN** 参加者が10秒の間に4件目のコメントを送る
- **THEN** 4件目は他の参加者に表示されず、送った人には少し待つよう表示される

#### Scenario: 空白だけのコメント

- **WHEN** 参加者が空白だけのコメントを送ろうとする
- **THEN** 送信の操作は使えず、サーバーに直接送っても受け付けない

#### Scenario: HTMLを含むコメント

- **WHEN** 参加者が `<b>太字</b>` と書いて送る
- **THEN** 入室者の画面には `<b>太字</b>` という文字のまま表示される

### Requirement: COMM-04 コメントを残さない

コメントは表示が終わったら破棄し、本アプリの保存先・PDS・サーバーのログに文面を残してはならない（MUST）。あとから入室した参加者に、入室前のコメントを表示しない。

#### Scenario: あとから入室する

- **WHEN** コメントが送られたあとに別の利用者が入室する
- **THEN** 入室前に送られたコメントは、流れる表示にも欄にも出ない

#### Scenario: サーバーのログ

- **WHEN** コメントを受け付けて配る
- **THEN** サーバーのログにはコメントの文面を残さない

### Requirement: COMM-05 botたんはコメントを読まない

botたんが参加しているSpaceでも、コメントをbotたんの会話（convo）に渡してはならない（MUST）。botたんは今までどおりスピーカーの発話（字幕）にだけ返事をする。

#### Scenario: botたんの参加中にコメントが届く

- **WHEN** botたんが参加しているSpaceで、聴衆が「botたんこんにちは」とコメントする
- **THEN** コメントは入室者に表示されるが、botたんには届かず、botたんはコメントに返事をしない
