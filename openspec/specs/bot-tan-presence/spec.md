# bot-tan-presence Specification

## Purpose
Spaceにbotたんをいつでも招待・除外でき、botたんがbot-tan-convoを通じて複数のスピーカーと声で会話し、3Dモデルで表示されるようにする。convoの処理能力の上限を超えたときの扱いも定める。

## Requirements

### Requirement: BOT-01 botたんの招待と除外

ホストは開催中のパブリックSpaceにいつでもbotたんを招待し、いつでも除外できなければならない（MUST）。botたんSpaceでは、botたんは開始時に参加し（LIFE-02）、除外の操作を出さず、サーバーも除外を受け付けてはならない（MUST）。招待と除外はホストだけができ、スピーカーと聴衆にはこの操作を出さず、サーバーも受け付けてはならない（MUST）。botたんは人間のロール（ホスト・スピーカー・聴衆）に数えず、参加者一覧ではbotたんであることが分かるように表示する。

#### Scenario: ホストがbotたんを招待する

- **WHEN** パブリックSpaceのホストがbotたんを招待し、convoに空きがある
- **THEN** 数秒以内にbotたんがSpaceに加わり、参加者一覧と3Dモデルが表示される

#### Scenario: ホストがbotたんを除外する

- **WHEN** パブリックSpaceのホストがbotたんを除外する
- **THEN** botたんの発話が止まり、Spaceから退出し、convoのセッションを解放する

#### Scenario: botたんSpaceで除外しようとする

- **WHEN** botたんSpaceのホストの画面、またはサーバーへの直接の要求でbotたんの除外を試みる
- **THEN** 除外の操作は表示されず、サーバーも要求を拒否し、botたんは参加したままである

#### Scenario: スピーカーが招待を試みる

- **WHEN** スピーカーのクライアントが、Space管理APIへbotたんの招待を直接要求する
- **THEN** サーバーは要求を拒否し、botたんは参加しない

### Requirement: BOT-02 convoの空きが無いとき

同時に参加できるbotたんの数はconvoのセッション数で決まる。空きが無いときは招待の操作を「botたんは今いっぱい」と表示して使えなくし、招待を受け付けてはならない（MUST）。待ち行列は作らない。空きができたら、招待の操作を再び使えるようにする。

#### Scenario: 空きが無い

- **WHEN** 他のSpaceがconvoのセッションをすべて使っている
- **THEN** 招待の操作は使えず、「botたんは今いっぱい」と表示される

#### Scenario: 空きができる

- **WHEN** 他のSpaceがbotたんを除外して空きができる
- **THEN** 開いているSpaceの招待の操作が再び使えるようになる

### Requirement: BOT-03 話者ごとの名前付きの発話で会話する

botたんには、各スピーカーの発話を話者ごとに分けて文字起こしし、話者の表示名を付けて渡さなければならない（MUST）。botたんは誰が話したかを区別して、全肯定の人物設定のまま返事をする。botたんの声はSpaceの入室者全員に届ける。

#### Scenario: 2人のスピーカーがbotたんと話す

- **WHEN** スピーカーAとスピーカーBが順に話す
- **THEN** botたんはAとBの発話を区別して受け取り、話者を取り違えずに返事をする

### Requirement: BOT-04 人間が話し始めたら譲る

botたんが話している途中でスピーカーの声がしたら、botたんはいったん話すのを止めなければならない（MUST）。その声が合わせて1秒以上続いたら、botたんは話すのをやめ、まだ再生していない返事を全員の画面で破棄する（MUST）。1秒続かずに声が途切れたら（相づちや物音）、止めたところから続きを話す（MUST）。いったん止めたまま4秒たっても判断がつかなければ、続きを話す。1秒は space-agent の設定で変えられる。聴衆の音声はbotたんに届かない。

#### Scenario: botたんの返事中にスピーカーが話す

- **WHEN** botたんが話している途中でスピーカーが話し始め、1秒以上話し続ける
- **THEN** botたんの音声が止まり、まだ再生していない返事は全員の画面で破棄される

#### Scenario: 相づちを打つ

- **WHEN** botたんが話している途中で、スピーカーが「うん」と短く相づちを打つ
- **THEN** botたんはいったん止まるが、すぐに止めたところから続きを話す

### Requirement: BOT-05 3Dモデルの表示

botたんが参加している間、入室者全員の画面にbotたんの3Dモデル（VRM）を表示し、待機の動き、話している間の口の動き、返事に合わせた体の動きを再生しなければならない（MUST）。話していない間の身振り・表情・目線は BOT-12 で定める。3Dモデルは、Space画面の見出しのすぐ下に、画面の主役として大きく表示する（MUST）：スマートフォン（幅1024px未満）では画面の幅いっぱい（広くても640px程度）とし、上半身が画面の高さの半分ほどを占める大きさにする。幅1024px以上の画面では、左の段の幅いっぱいに、画面の高さの70%まで大きく表示する（LOOK-07）。3Dを表示できない端末では、botたんのアイコンを同じ場所に大きく表示する。

#### Scenario: botたんが話す

- **WHEN** botたんが返事を話す
- **THEN** 3Dモデルの口が音声に合わせて動き、返事に合った体の動きを再生する

#### Scenario: スマートフォンで表示する

- **WHEN** 幅360pxの画面でbotたんが参加しているSpaceを開く
- **THEN** 3Dモデルが画面の幅いっぱいに表示され、横スクロールは出ない

#### Scenario: 広い画面で表示する

- **WHEN** 幅1280pxの画面でbotたんが参加しているSpaceを開く
- **THEN** 3Dモデルが左の段の幅いっぱいに表示され、その右に字幕とコメントの欄が並ぶ

#### Scenario: WebGLが使えない

- **WHEN** 入室者のブラウザでWebGLが使えない
- **THEN** 3Dモデルの代わりにbotたんのアイコンを同じ場所に大きく表示し、音声と字幕は通常どおり届く

### Requirement: BOT-12 待機中の身振り・表情・目線

botたんが話していない間も、まばたきをし、表情を少しずつ動かし（ときどきほほえむ）、数十秒おきに作り置きの動きからしぐさを1つ流さなければならない（MUST）。目線は画面のこちら側（見ている人）に向け、数秒おきに少しずつ見る位置を変え、ときどきそらしてすぐ戻す（MUST）。動きを流している間も目線はこちらに向けたままにする。しぐさは返事の動きと重ねず、返事の動きが届いたらそちらを優先する。端末で「視差効果を減らす」を選んでいる人には、しぐさを流さない（まばたきと表情は動かす）。

#### Scenario: 話していない間

- **WHEN** botたんが参加していて、しばらく話していない
- **THEN** botたんはまばたきをし、表情が少しずつ変わり、数十秒おきにしぐさを1つ流す

#### Scenario: 目線

- **WHEN** botたんが参加している Space を開く
- **THEN** botたんの目線は画面のこちら側を向き、ときどき少し動いて戻る

#### Scenario: しぐさの途中で返事をする

- **WHEN** しぐさを流している途中で、botたんが返事を話し始める
- **THEN** 返事に合った体の動きに切り替わる

#### Scenario: 視差効果を減らしている

- **WHEN** 端末で「視差効果を減らす」を選んでいる入室者が、botたんが参加している Space を開く
- **THEN** しぐさは流れず、まばたきと表情だけが動く

### Requirement: BOT-06 convoの障害

convoに接続できないか、会話中に接続が切れたときは、botたんを退出扱いにしてホストに知らせなければならない（MUST）。パブリックSpaceでは、人間どうしの音声と字幕は止めてはならない（MUST）。botたんSpaceでは、botたんが退出している間は字幕も止まり、ホストに「もう一度呼ぶ」操作を示す（MUST）。convoやbotたんの中継に届かない間は、招待の操作を「botたんは今お休み中」と表示して使えなくし、botたんSpaceも作らない（MUST）。空きが無いとき（BOT-02）の「いっぱい」とは表示を分ける。届くようになったら、招待の操作を再び使えるようにする。

#### Scenario: 会話中にconvoが止まる

- **WHEN** パブリックSpaceでbotたんの参加中にconvoへの接続が切れる
- **THEN** botたんが退出したと表示し、ホストに再招待の操作を示し、人間の会話と字幕は続く

#### Scenario: botたんSpaceでconvoが止まる

- **WHEN** botたんSpaceでbotたんの参加中にconvoへの接続が切れる
- **THEN** botたんが退出したと表示し、字幕は止まり、ホストに「もう一度呼ぶ」操作を示す。呼び直すとbotたんと字幕が戻る

#### Scenario: convoに届かない間に招待しようとする

- **WHEN** convoかbotたんの中継が止まっている間に、ホストがbotたんの招待の操作を見る
- **THEN** 招待の操作は使えず、「いっぱい」ではなく「botたんは今お休み中」と表示される

#### Scenario: convoに届かない間にbotたんSpaceを作成する

- **WHEN** convoかbotたんの中継が止まっている間に、botたんSpaceを作成しようとする
- **THEN** Spaceを作成せず、「botたんは今お休み中」と表示する

### Requirement: BOT-07 Spaceの会話はbotたんの記憶に残さない

パブリックSpaceとbotたんSpaceのどちらの会話も、botたんの記憶（convoのBot Memory API）に書き込んではならない（MUST）。botたんSpaceの会話を記憶に残す仕組みは、利用者ごとに分けて引く方法とあわせて別のchangeで扱う（2026-11-27 利用者と決定）。

#### Scenario: パブリックSpaceで話す

- **WHEN** botたんがパブリックSpaceで複数のスピーカーと会話する
- **THEN** その会話の内容はbotたんの記憶に書き込まれない

#### Scenario: botたんSpaceで話す

- **WHEN** ホストがbotたんSpaceでbotたんと話し、Spaceを終える
- **THEN** その会話の内容はbotたんの記憶に書き込まれず、次のbotたんSpaceでbotたんは前回の会話を覚えていない

### Requirement: BOT-08 botたんSpace でホストの最近の投稿を踏まえて話す

botたんSpace で botたんが会話を始めるとき、ホストの直近7日間の Nagi の投稿のうち新しい順に最大20件を、botたんの会話に渡さなければならない（MUST）。こっそり投稿・CW 付きの投稿・ラベル付きの投稿は渡してはならない（MUST）。パブリックSpace では、ホストを含め誰の投稿も渡してはならない（MUST）。渡した投稿は会話の間だけ使い、本アプリの保存先・botたんの記憶・ログに残してはならない（MUST。BOT-07・LIFE-07）。投稿を読めなかったときは、投稿なしで会話を始め、botたんの参加を止めてはならない（MUST）。

#### Scenario: 最近の投稿に触れる

- **WHEN** 3日前に「新しいカフェに行った」と Nagi に投稿したホストが、botたんSpace で botたんと話す
- **THEN** botたんはその投稿を踏まえて話題にできる

#### Scenario: パブリックSpace

- **WHEN** botたんがパブリックSpace に参加する
- **THEN** ホストやスピーカーの投稿は botたんに渡されない

#### Scenario: こっそり投稿やCW付きの投稿

- **WHEN** ホストの直近の投稿に、こっそり投稿・CW 付き・ラベル付きの投稿が含まれる
- **THEN** それらは botたんに渡されない

#### Scenario: 投稿を読めない

- **WHEN** ホストの PDS に届かない
- **THEN** botたんは投稿なしで参加し、会話は通常どおり始まる

### Requirement: BOT-09 沈黙したら botたんから話しかける

botたんが参加している Space（パブリック・botたんSpace のどちらも）で、15秒間だれも話さず botたんも話していないときは、botたんから話題を振らなければならない（MUST）。話しかけたあとは、次に話しかけるまで最低30秒あける（MUST）。話題は Space のタイトルや直前までの会話から選び、botたんSpace では BOT-08 の投稿も使える。パブリックSpace では特定の人の投稿に触れない。人が話し始めたら、botたんは話すのをやめる（BOT-04）。

#### Scenario: 会話が止まる

- **WHEN** botたんが参加している Space で、15秒間だれも話さない
- **THEN** botたんから短く話題を振る

#### Scenario: 続けて沈黙する

- **WHEN** botたんが話しかけたあとも、だれも話さない
- **THEN** botたんは最低30秒たつまで次の話しかけをしない

### Requirement: BOT-10 話題から関連する記憶を引く

botたんが参加している Space（パブリック・botたんSpace のどちらも）で、会話の話題に関係する botたんの記憶を引き、返事に織り込めるようにしなければならない（MUST）。引く記憶は、botたん自身の体験（biorhythm）と、botたんが調べて覚えた知識（web_research）だけとし、ほかの利用者の投稿・受け取った返信・リアクション・配信のコメントは引いてはならない（MUST）。記憶は読むだけで、Space の会話を記憶に書き込んではならない（BOT-07）。記憶を引くあいだは短いつなぎの言葉を話し、記憶に届かないときは記憶なしで返事をして、会話を止めてはならない（MUST）。

#### Scenario: 話題に関係する体験を思い出す

- **WHEN** スピーカーが「最近どこか出かけた？」と botたんに聞き、botたんの記憶に先週出かけた記録がある
- **THEN** botたんはその体験を踏まえて答える

#### Scenario: 調べて覚えた知識を使う

- **WHEN** スピーカーが、botたんが前に調べて覚えたゲームの名前を出す
- **THEN** botたんはその知識を踏まえて話せる

#### Scenario: ほかの人の投稿は引かない

- **WHEN** パブリックSpace で、botたんが以前全肯定したほかの利用者の投稿と同じ話題が出る
- **THEN** botたんはその投稿を記憶から引かず、場に持ち出さない

#### Scenario: 記憶に届かない

- **WHEN** Bot Memory API に届かない
- **THEN** botたんは記憶なしで返事をし、会話は続く

### Requirement: BOT-11 いまの様子と日々のまとめ

botたんが参加している Space（パブリック・botたんSpace のどちらも）で、botたん自身のいまの様子（していること・元気・天気）を聞かれたら、それを踏まえて答えなければならない（MUST）。聞かれていないときに自分から様子を話題にはしない。また、botたんの最近の出来事のまとめ（直近2日）を会話の前提にする。どちらも botたん自身のことだけで、ほかの利用者の情報を含めてはならない（MUST）。取得できないときは、それなしで会話を続ける。

#### Scenario: 元気かと聞かれる

- **WHEN** スピーカーが「botたん、今日は元気？」と聞く
- **THEN** botたんはいまの自分の元気や様子を踏まえて答える

#### Scenario: 様子を取得できない

- **WHEN** botたんのいまの様子を取得できない
- **THEN** botたんは様子に触れずに答え、会話は続く
