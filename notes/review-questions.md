## 夜間作業での判断

### 作業5.1

- ローカルの LiveKit を v1.9.0 から **v1.13.0** に上げた（クライアント 2.25 とプロトコルが合わず、マイクの送信が失敗していた）。本番の LiveKit Cloud は常に最新なので影響しない。
- ローカルの LiveKit は接続先のIPを自動で検出させる（127.0.0.1 を指定すると Chrome が接続候補に使わなかった）。
- E2E は通常の Chromium（新しい headless）で動かす。軽量の headless shell はマイクの取得に対応しない。

### 作業5.2・5.3

- 承認・招待は「スピーカーになれる申し出」として扱い、本人がマイクを許可して受け入れたときにスピーカーになる。申し出は10分で消える。
- 承認・招待のあと、字幕の案内（TRANS-02）と「マイクを許可してスピーカーになる」ボタンを出し、押したときに許可を求める（自動では許可の画面を出さない）。
- マイクを拒否したときは申し出を残し、あとで同じボタンから再試行できる。
- スピーカーの上限は、承認・招待・受け入れのそれぞれで確かめる。
- ホストへの「リクエストが変わった」通知と、本人への「承認・招待された」通知は、サーバーからの決まった形の通知だけで送る（自由な文章を含まない。design.md D8）。
- 聴衆に戻るとマイクを自動で止める。

### 作業5.4

- 退室させる操作は、誤操作を避けるため画面内で確認してから行う（ブラウザのダイアログは使わない）。
- ホストはスピーカー・聴衆の誰でも退室させられる。退室させた人が持っているトークンも無効にし、そのまま再接続できないようにする。
- 再入室の禁止は Space の終了で消す（「その Space の間だけ有効」）。

### 作業5.5・5.6（通報）

- **bsky-affirmative-bot のブランチ `nagi-space-report`（コミット b5af6c07、未push）**で、`createReport` に Space の通報（`subject.space`）を足した。既存の通報はそのまま動く。lexicon の公開（`lex:publish`）と AppView のデプロイは未実施。これが本番に出るまで、Nagi Space の通報は失敗する。
- AppView は Space の存在を確かめられないため、Nagi Space から送った値をそのまま Discord に載せる（乱用は既存の1時間10件の枠で抑える）。
- 理由の選択肢は Nagi と同じ5つ（「botたんの返答へのフィードバック」を含む）。既定は「攻撃的・いやがらせ」。
- ホストには自分の Space を通報する操作を出さない（参加者の通報はできる）。自分自身は通報できない。

### 作業5.9・5.10

- Nagi のミュートの一覧が取れなかったときは、何も隠さずに表示する（ミュートは表示の好みなので、取得の失敗で操作を止めない）。ミュートの一覧は本人ごとに5分覚える。
- 作成の許可リストは環境変数 `SPACE_CREATOR_ALLOWLIST`（DIDのカンマ区切り）。本番で設定するかは任意（総合通信局への相談はしないと決めたため、相談待ちの理由は無くなった）。入室は制限しない（許可リストの人が作ったパブリックSpaceには誰でも入れる）。

### 作業6.1・6.2（絵文字）

- 連投制限は「1人あたり10秒に8個」。超えた分は配らず、送った人に「少し待ってから」と出す。
- 絵文字の表示時間は約4秒。画面に同時に出すのは最大20個。
- 検索していないときは「お気に入り → 最近使った絵文字 → よく使う絵文字8個（👏😂🥰🎉🙌💯🔥👀）」の順に出す。最近使った絵文字はこの端末だけに保存する（Nagi と同期しない）。
- お気に入りの絵文字が取れなかったときは空にする（送信はできる）。
- Unicode 絵文字は「絵文字1つ」だけを受け付け、任意の文章を流せないようにした。カスタム絵文字は AppView で今も存在するものだけを受け付け、表示用のURLは AppView の値を使う。
- 連投制限の数え上げのため、**マイグレーション `db/migrations/0002_nagi_space_kv_incr.sql` を追加**した（自宅DBにも適用が必要）。

### 作業7（bot-tan-convo）

- **bot-tan-convo のブランチ `nagi-space`（別の作業ディレクトリ `../bot-tan-convo-nagi-space`、未push）**に変更を置いた。main にあった作業中の変更（`ardy/serve.py`）には触れていない。説明は convo の `docs/nagi-space.md`。

### 作業8（space-agent）

- **LiveKit の agent dispatch は使わず、space-agent が数秒ごとに Nagi Space と同期する形にした**（design.md D5）。自宅から外への通信だけで済み、LiveKit Cloud でもセルフホストでも同じに動く。共有の秘密は環境変数 `AGENT_SECRET`。
- botたんが自分から抜けた（convo の障害など）ときは、招待を取り消してホストに「接続が切れたため退出しました」と知らせる。失敗した Space には30秒は入り直さない。
- 字幕の欄は入室してからの字幕を最大200行持つ（さかのぼらない）。botたんの字幕は、割り込まれたときは実際に話したところまでにする。
- botたんの招待のボタンは「botたんを呼ぶ」「botたんに抜けてもらう」の文言にした。空きの確認は5秒ごと。
- **【未対応】作業8.7（botたんSpace の会話を記憶に残す）**は、作業7の記録のとおり判断待ち。
- E2E は本物の space-agent を偽の convo とつないで動かしている（本物の convo・GPU は使わない）。本物の convo とつないだ確認は、自宅で一度行う必要がある。

### 作業9.1（3Dモデル）

- **botたんの VRM と動きはリポジトリに置かない**ことにした（VRM 約13MB・動き約16MB。bot-tan-room も非公開の R2 から配っている）。本番は `BOT_ASSETS_BASE_URL` の置き場から読む。**置き場への配置と CORS の設定は利用者の作業（作業2.6として追加）**。
- 使う動きのカテゴリは neutral・happy・greeting・encouraging・surprised・thinking・dance と待機（idle）。各6本まで。pat・custom は使わない。
- botたんのアイコン（WebGL が使えないとき）は nagi_client の `static/bot_icon_trans.png` を `static/bot-tan-icon.png` として写した。
- カメラの位置は、スマホ幅で頭から太ももくらいまでが入る（スクリーンショットで確認）。同じ動きが続いたときに T ポーズになる不具合を直した。

### space-agent の不具合の修正

- **Space が始まってすぐ終わると、space-agent のプロセスごと落ちる不具合**を見つけて直した。LiveKit の Python SDK は、room への接続の途中で待ちを取り消すと中の部品が時間切れになりプロセスを止める。接続の途中では取り消さず、つなぎ終えてから抜けるようにした。本番でも systemd などで space-agent を自動で再起動する設定を推奨。
- 止まったときの調べ物のため、`kill -USR1 <pid>` で全スレッドの状態を出せるようにした。
